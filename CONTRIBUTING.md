# Contributing

Begin with PROJECT_STATUS.md, DECISIONS.md, ROADMAP.md, LEARNING_LOG.md, and the issue backlog. Keep work confined to this project. Use a branch and PR for substantive changes once a remote exists.

Before implementing a meaningful change, state the intended behavior, rationale, concepts, alternatives, and acceptance evidence. Afterward, report what changed, tests, remaining uncertainty, and the next task. Update continuity files and use small descriptive commits.

Run `python3 -m unittest discover -s tests -v`. New rules need reviewed positive and negative scenarios, traceable input facts, priority reasoning, evidence requests, and primary-source references. Do not generate expected rule results from the implementation under test.

Use synthetic data. Do not add credentials, personal information, real assessment data, or copied proprietary standards. Keep framework mappings separate from compliance claims. Review staged content before committing.

Approval is required before public repository creation/visibility changes, costs, external infrastructure, sensitive account/data connections, personal-information publication, destructive changes, external active security testing, or a substantial change of direction. Routine local work, tests, commits, and authorized-project issue management may proceed autonomously.
